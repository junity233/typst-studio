# Agent Note: Fourth deduplication pass — workspace-open flow, confirm helper, open-doc lookup, dead surface

Status: implemented

## Problem

A fourth sweep (after [pass 1](2026-08-15-codebase-dedup-pass.md),
[pass 2](2026-08-15-dedup-pass-2.md) and
[pass 3](2026-08-16-dedup-pass-3.md)) targeted families the earlier passes
hadn't spotted, including one with live behavioral drift:

- The workspace-open tail (set `rootPath`/`name`/`tree`/`expanded` →
  `refresh("")` → `recordWorkspace` → `projectConfigStore.hydrate`) was
  written three times: `workspaceStore.openWorkspace`,
  `useAppCommands.handleOpenRecent` (its comment admitted the mirror), and
  `PackageDetail.runInit` — which skipped `recordWorkspace`, so a project
  created from a package template never appeared in Open Recent.
- "Is this file already open?" was scanned five ways: `openFile` /
  `exportTarget` / `batchExportStore` via `workspacePathsEqual`, but
  `assistantStore` + `assistantTools` via `lib/assistantPath.pathsEqual`,
  which lowercases unconditionally — on POSIX, two docs differing only by
  case would falsely collide.
- The `useDialogStore.getState().confirm({...}); if (result !== "confirm")
  return;` idiom appeared at 10 sites; 7 of them never look at `discard`.
- `enablement: () => useTabsStore.getState().activeId !== null` was
  byte-identical at 10 command registrations across 4 extensions, and the
  workbench `export`/`export-pdf`/`-png`/`-svg` registrations were 4 copies
  differing only in the pinned format.
- Dead surface: the whole `sourceControl` i18n namespace (+ the doubly-dead
  `workbench.scm` ActivityBar mapping), the `__smoke__` key in 13
  namespaces, `commandBar.untitled/unsavedChanges`, `titlebar.dirtyTooltip`,
  `common.yes/no`, the `@codingame/monaco-vscode-languages-service-override`
  dependency (zero imports), backend `DocumentService::docs_under_path`
  (test-only), `RecoveryService::recovery_dir`, the `RecoveryService.
  debounce` and `LspManager.config` fields (both `#[allow(dead_code)]`
  with the claimed test/user absent).
- Backend preludes: the image-extension array hardcoded at the two
  `ipc::commands` dialog filters instead of `domain::file_kind::
  IMAGE_EXTENSIONS` (whose doc said "kept in sync by hand"); the
  exclude-globset build prelude ×3 (`search_workspace`,
  `replace_in_files`, `list_typ_files`); the five `git_commands` wrappers
  repeating root+`spawn_blocking`+label-map+join-map; `settings::validate`
  carrying byte-identical `"string"` and `"font" | "path"` match arms.
- Test side: every `.test.tsx` hand-rolled the same createRoot/act
  render/cleanup harness (~15 files, IS_REACT_ACT_ENVIRONMENT included
  only once).

## Decision

Extract one canonical home per family; behavior differences stay at call
sites as data. No wire format, event name, or command signature changed.

- `workspaceStore.openWorkspaceByPath(path) -> boolean` is the canonical
  programmatic open (open-recent menu, package template init);
  `adoptOpenedWorkspace(meta)` is the shared tail also used by the
  dialog-based `openWorkspace`. The template-init drift is fixed: template
  destinations now reach Open Recent. Pinned by the new
  `store/__tests__/workspaceStore.openByPath.test.ts`.
- `documentsStore.findOpenDocByPath(abs)` is the one "find the open doc
  at this path" lookup (documents map incl. backend-only tabs,
  `workspacePathsEqual`). `assistantStore`/`assistantTools`/`
  `exportTarget`/`batchExportStore` funnel through it; `openFile` keeps
  `readAllDocuments()` (tab-or-hidden-only set, needed for activation);
  `lib/assistantPath.pathsEqual` lost its last production caller and was
  deleted with its tests. Pinned by
  `store/__tests__/documentsStore.findOpenDocByPath.test.ts` (Windows
  case-insensitive, POSIX case-sensitive, null-path skip).
- `dialogStore.confirmAction(req) -> Promise<boolean>` resolves true only
  on confirm; adopted at the 7 two-way sites (Settings clear actions,
  Explorer delete, Bibliography/InstalledList/PackageDetail/ProjectPanel
  confirms, the save-failed Save-As offer). The three-way
  save/close dialogs keep raw `confirm`. Pinned in
  `store/__tests__/dialogStore.test.ts`.
- `tabsStore.hasActiveTab()` is the shared enablement predicate (10 sites);
  the workbench export commands register from a 4-entry format table
  (`export` pins nothing → `defaultExportFormat`). Pinned by a new
  live-state enablement test in `extensions/__tests__/
  workbench.commands.test.ts`.
- Dead surface deleted (see Problem for the inventory); `docs_under_path`
  is `#[cfg(test)]` (its visible-only semantics stay pinned by the
  document_service tests) with intra-doc links converted to plain text.
- Backend preludes: both dialog filters reference `IMAGE_EXTENSIONS`
  directly; `ProjectConfigService::exclude_globset()` replaces the three
  read-config+build-globset preludes; `ipc/git_commands::run_git` owns the
  root+spawn_blocking+label tail for the five git commands (same file,
  same error strings — not the pass-1-rejected generic `run_blocking`);
  `settings::validate` matches `"string" | "font" | "path"` in one arm.
- `src/test/react.tsx` (`reactHarness()`: render/renderAsync/rerender/
  unmount/cleanup, sets IS_REACT_ACT_ENVIRONMENT) replaces the
  per-suite createRoot boilerplate in the 15 `.test.tsx` files.

## Alternatives considered

- Delegating `openWorkspace` through `openWorkspaceByPath` (one canonical
  path): rejected — it would re-open the already-dialog-opened root on the
  backend; `adoptOpenedWorkspace` shares the tail without double IO.
- Recording the workspace in `hydrate`'s session-restore path too:
  skipped — restore shouldn't reorder the recent list on every launch.
- Folding `openFile`'s scan into `findOpenDocByPath`: rejected — its
  candidate set is tabs/hidden only (a lingering backend-only tab must
  not be "reactivated" from a double-click).
- A `hasOpenWorkspace` sibling for the two `rootPath !== null` enablement
  sites: skipped — only 2 occurrences, below the family bar.
- Unifying the four backend `.typ` walkers (drift table now recorded in
  pass 3's note): still deferred — which exclude/case policy wins differs
  per frontend surface and needs its own decision.
- The modal shell for the 8 dialog components: still deferred (4 portal
  vs 4 inline; stacking behavior needs visual verification).
- Remaining known families left for a future pass: ProjectPanel's five
  label+control+browse field rows (~80 lines), the Explorer/TabStrip
  copy-path submenu builders, the sidebar debounce/visible-once hooks,
  `useBusyAction` for Settings busy blocks, `vi.mock("@tauri-apps/api/core")`
  and `vi.mock("../lib/tauri")` factories across ~30 test files, and the
  fake `vscode` Uri duplicated in 3 Editor tests.

## Consequences

- Thirteen code/test commits plus the docs commit; the template→Open-Recent drift
  and the POSIX path-comparison drift are behavior fixes riding the same
  refactor, each pinned by a new test.
- New canonical homes to extend instead of copy: `openWorkspaceByPath`,
  `findOpenDocByPath`, `confirmAction`, `hasActiveTab`,
  `ProjectConfigService::exclude_globset`, `ipc::git_commands::run_git`,
  `src/test/react.tsx`.
- Verification: targeted vitest suites per commit + `tsc -b` clean;
  `cargo test` (settings/project_config/recovery/document_service/lsp
  filters green) + `cargo clippy --all-targets` clean except the known
  frozen-`git/` warning.
- `frontend-state.md` / `frontend-extensions.md` / `frontend-components.md`
  / `backend-layers.md` updated in the same PR.
